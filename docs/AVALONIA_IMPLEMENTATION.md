# DinoSaurList Core + CLI + Avalonia conversion

Requested by Jay Baek on 2026-11-18. Target repository is **DinoSourList-AppStore-Official-Release**; **NPISpectreConverter** is the architectural/update reference, not the application being refactored. Source baseline `fd4eca5`; reference `9d24a95`. Server planning document: `NPIServer/docs/DINOSAURLIST_AVALONIA_MIGRATION_PLAN.md` (`06a08a5`).

This branch is a **parallel preview**, not an assertion of complete behavioral parity. Existing Python entry points, release assets and user installations remain usable while the native implementation is validated. Do not replace the production release channel based only on these tests.

## Structure

- `dotnet/core`: catalogue, Flow/version parsing, Box Manager transport, checksum verification, extraction/install lifecycle, platform launcher, Windows MSI/delete/shortcut integration, installed versions/default selection, legacy import, settings/favourites/news, profiles/photos, local activity, TF-IDF retrieval and Velopack update orchestration.
- `dotnet/cli`: JSON stdout / diagnostic stderr host for Core. `help` lists catalogue/readme/guide/recommend/installed/install/launch/pin/remove/favourites/import-preview/import/settings/news/profile/photo/activity/update. Mutating remove/import/update-apply require `--yes`; profile writes and installs are explicit commands.
- `dotnet/app`: Avalonia UI, MVVM presentation state, native file picker/dialogs and image rendering. Storage and installed-version operations use the same Core services as the CLI.
- `dotnet/tests`, `dotnet/ui-tests`: behavioral and headless rendered UI tests. Legacy contract fixture captures actual Python version/name results and Python configparser expectations over 28 real Flow documents.

Target .NET 10 LTS: .NET 9 reached end of support 2026-11-10 (https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core). Avalonia 12.1.2, Toolkit 8.4.2, Velopack 1.2.158. The release update lifecycle uses `SimpleWebSource` with a public `GithubSource` fallback. No PAT is injected into binaries.

## Build and run

```sh
cd dotnet
dotnet build DinoSaurList.sln -c Release
dotnet test --solution DinoSaurList.sln -c Release --no-progress
dotnet run --project cli -- help
dotnet run --project cli -- catalogue --refresh --data-dir /tmp/dinosaurlist-preview
dotnet run --project app
```

The repository root pins the local `vpk` tool. As requested by Jay on 2026-11-19, `native-dotnet.yml` performs **headless build, packaging and deployment only**. Linux (`self-hosted-rocky`) prepares release metadata, publishes GitHub Releases and deploys the NPI feed. Windows (`self-host-win11`) and Apple Silicon macOS (`self-host-osx`) publish the app/Core/CLI and create Velopack packages. Installed SDKs are reused. No CI job runs tests, installs the generated package, launches the application or an external tool, captures screenshots, probes a display, or applies an update. The three diagnostic/proof workflows have been removed. Test sources and manual diagnostic scripts remain available for explicitly requested local investigation.

Push a `v*` version tag, or dispatch with `version` and `publish=true`, to build and publish both OS packages through an unpublished GitHub draft, then deploy them to NPI. Branch pushes do not build. Windows packaging uses the official [`--skipVeloAppCheck`](https://docs.velopack.io/reference/cli/content/vpk-windows) option to skip application verification; packaging commands are noninteractive. Upload sizes/hashes, both platform packages/feeds, exact source commit, licensing files and live-feed integrity remain part of packaging/distribution; no installed UI evidence is required. The NPI server retains its latest-two-version policy and protects files referenced by current feeds.

The sections below contain historical verification evidence. Their prior CI test/install/UI gates and proof workflows are superseded by this build-only policy.

The native Velopack package ID is `DinoSaurListNative` (display title DinoSaurList), so its Windows install root cannot collide with legacy `%LOCALAPPDATA%/DinoSaurList/dev_photos` or native data. Data defaults to per-user LocalApplicationData/DinoSaurList, outside that installation. Override with CLI `--data-dir` or UI `DINOSAURLIST_DATA_DIR`. Box defaults to the existing central Box Manager; its credential-free listing/download/upload API is shared by both hosts. Default update feed is `https://npi-service.kor.broadcom.net/dinosaurlist/`; the NPIServer repository owns its nginx route and download page. The app automatically checks and downloads releases in the background at startup. Velopack applies a prepared update on the next start; Settings also offers immediate restart. Failure to reach the default NPI feed falls back to public GitHub Releases without credentials. The GitHub repository URL can also be saved as the preferred feed. Custom HTTPS feeds do not silently fall back to a different publisher. No native code monitors main or runs the old Python updater. Automatic startup updates are skipped in installer smoke mode so verification is repeatable. See [Velopack's update lifecycle](https://docs.velopack.io/integrating/overview) and [public GitHub source](https://docs.velopack.io/integrating/update-sources).

## Current release operations (2026-11-18)

The production path is `v*` tag -> Linux tests -> Windows/macOS self-hosted package and installed-workflow verification -> authenticated draft staging -> GitHub publication -> the existing `self-hosted-rocky` server's `/var/www/dinosaurlist/`. Branch pushes do not publish. Both platform checks must succeed before publication; SDKs are reused. Staging uses static PowerShell on Windows and Bash on macOS, avoiding the missing Windows Bash and invalid workflow shell expression from superseded candidates. Run 44272462564 (.19) passed every job. Public Mac .13 -> .18 download, SHA256, next-start application, updated UI and existing-data preservation passed run 44272212846.

Comparison: NPISpectreConverter and ATEDataAutoLinkFCM default-branch (master) release workflows use version tags, self-hosted native builds, GitHub Releases and this server, pruning to two nupkg files globally by modification time. CsvTool publishes binaries before atomically replacing manifests. DinoSaurList follows these deployment boundaries, but retains **two versions per OS/channel**, ranked by SemVer; every package referenced by current JSON or legacy RELEASES manifests is additionally protected. GitHub historical releases remain available. Unknown package families are untouched. The server's npi-cleanup cron does not manage native releases.

`verify-native-feed.py` checks both platform package sizes, SHA256 and expected version before live changes. The deploy script publishes package bytes before atomic manifests, then `prune-native-feed.py --keep 2 --apply` bounds history and regenerates list.json. The pruning command defaults to a dry run. Malformed feeds or missing referenced files prevent pruning. Eight release-feed regression tests cover corruption, version mismatch, path escape, unchanged live files on invalid input, numeric version ordering, independent OS/channels, live-reference preservation and real deployment/list regeneration. The workflow removes only its run-specific temporary download directory even after failure.

The application now exposes Dashboard update/restart controls and periodic automatic checks; external process starts and assistant indexing run off the UI thread. Profile IPv4/vector icons, the conversation assistant and official main-branch News/news.md/version.json content are restored. Unsupported Windows packages can be downloaded on Mac without attempting to execute them. Small-window sidebar scrolling keeps navigation above the profile footer. Full original-Python behavioral parity and every third-party installer remain separate verification work; passing these checks is not a claim of universal equivalence.
